本仓库的错误处理采用 Python 标准异常 + loguru 结构化日志的组合方式，围绕 WebSocket 直播连接生命周期组织，未引入第三方错误框架或统一错误码体系。

1. 系统/方法
- 自定义异常：在 `live_streams/exception.py` 中仅定义了一个 `AuthError(Exception)` 子类，用于表示认证失败场景。
- 标准异常：广泛使用 `KeyError`（参数缺失、房间不存在）、`struct.error`（协议解析失败）、`json.JSONDecodeError`、`asyncio.CancelledError`、`TimeoutError`、`websockets.exceptions.ConnectionClosedError` 等内置异常。
- 日志记录：通过 `loguru.logger` 以 `[room_id]` 前缀输出结构化日志，区分 `error` / `warning` / `info` / `debug` / `success` 级别。
- 无全局中间件：错误处理分散在各方法的 try/except 块中，没有统一的异常拦截中间件。

2. 关键文件与位置
- `live_streams/exception.py`：唯一自定义异常 `AuthError`。
- `live_streams/__init__.py`（BLiveClient）：WebSocket 连接、认证、心跳、消息解析的核心错误处理逻辑。
- `main.py`：入口程序的环境变量校验与进程级取消信号处理。
- `utils/tools.py`：配置加载、WBI 签名缓存的异常捕获与日志记录。

3. 架构与约定
- 认证失败路径：`_on_message` 收到非 OK 的 AUTH_REPLY 时，记录错误日志并 raise `AuthError`，由调用方（start 中的 run 协程）的 except websockets.exceptions.ConnectionClosedError 分支捕获并记录。
- 网络 I/O 错误：aiohttp 请求后统一调用 `response.raise_for_status()`，将 HTTP 状态码转换为异常；websockets 连接关闭通过 `ConnectionClosedError` 捕获并记录。
- 协议解析错误：`struct.error` 被捕获后记录 payload 和 offset，不向上抛出，保证消息循环继续。
- 文件写入错误：`_write_file` 捕获通用 `Exception`，记录 warning 并返回 False，不影响主流程。
- 异步任务清理：所有启动的任务（心跳、主循环）在 finally 块中 cancel 并等待超时（5s），超时记录 warning，CancelledError 被忽略。
- 配置加载错误：`ConfigManage.__init__` 对 FileNotFoundError、TOMLDecodeError 和其他异常分别记录 error 并重新 raise。
- 环境变量校验：`main.py` 在缺少 `LIVE_ROOM_ID` 时直接 raise KeyError；`convert_str_to_list` / `convert_str_to_list_int` 在格式非法时记录 error 并 raise。

4. 约定与约束
- 认证相关错误必须通过 `AuthError` 抛出，以便上层区分认证失败与其他异常。
- 所有外部 I/O（HTTP、WebSocket、文件、pickle）均包裹 try/except，记录结构化日志后选择恢复或向上抛出。
- 异步取消通过 `asyncio.CancelledError` 捕获，不在异常链中传播，确保资源释放。
- 未使用 panic/recover 模式（Python 无此概念），也未定义统一错误码枚举；API 层通过 logger.warning 打印业务 code（如 send_msg 的 -101、-111、-400、1003212、10031 等）而非抛出自定义异常。
- 日志统一使用 loguru，按文件轮转（每日 00:00）并异步写入，便于问题回溯。
