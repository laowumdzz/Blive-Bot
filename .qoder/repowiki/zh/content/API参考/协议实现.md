## 简介
本文件面向B站互动协议V2的客户端实现，系统性说明WebSocket连接建立、消息格式、协议版本与兼容性、心跳机制、重连策略、错误处理与性能优化。文档同时提供完整的消息序列化与反序列化示例路径，并给出与B站官方协议的差异点及适配方案，最后附带调试工具与故障排除指南，帮助开发者快速定位问题并稳定运行。

## 架构总览
整体采用“连接层-编解码层-事件层”的分层架构。连接层维护WebSocket生命周期；编解码层负责协议帧组装与解析；事件层根据消息类型分发给业务处理器。配置模块集中管理连接参数与行为开关，异常模块统一错误语义。

```mermaid
sequenceDiagram
participant App as "应用(main.py)"
participant WS as "连接管理"
participant Codec as "编解码器"
participant Router as "事件路由器"
participant Handler as "业务处理器"
participant Conf as "配置(枚举/配置)"
App->>Conf : 加载配置(房间ID/版本/超时)
App->>WS : 建立WebSocket连接
WS-->>App : 连接成功回调
App->>Codec : 发送握手/鉴权消息
Codec-->>WS : 编码后帧
WS-->>Codec : 接收原始帧
Codec->>Router : 解析为结构化消息
Router->>Handler : 按类型分发
Handler-->>App : 业务结果/状态上报
Note over WS,Codec : 心跳/重连由连接层驱动
```

## 详细组件分析

### 连接管理与心跳重连
- 连接建立：读取配置中的服务器地址、端口、TLS选项、鉴权参数，发起WebSocket握手
- 心跳机制：周期性发送心跳帧，服务端未响应时触发重连
- 重连策略：指数退避+抖动，最大重试次数与退避上限可配置
- 优雅关闭：在退出前发送关闭帧并等待确认

```mermaid
flowchart TD
Start(["开始"]) --> LoadCfg["加载连接配置"]
LoadCfg --> Connect["建立WebSocket连接"]
Connect --> Auth{"鉴权成功?"}
Auth --> |否| RetryAuth["重试鉴权(限次)"]
RetryAuth --> Auth
Auth --> |是| Heartbeat["启动心跳循环"]
Heartbeat --> RecvMsg{"收到消息?"}
RecvMsg --> |是| Decode["解码并路由"]
Decode --> Handle["业务处理"]
Handle --> RecvMsg
RecvMsg --> |否| CheckHB{"心跳超时?"}
CheckHB --> |是| Reconnect["指数退避重连"]
CheckHB --> |否| Heartbeat
Reconnect --> Connect
```

## 性能考量
- 连接复用：长连接减少握手开销
- 批量发送：合并小消息降低系统调用
- 零拷贝：尽量使用内存视图与缓冲池
- 异步I/O：非阻塞收发提升吞吐
- 压缩策略：仅在带宽受限场景启用
- 背压控制：消费端速率限制防止积压

## 故障排除指南
- 连接失败：检查网络可达、防火墙、证书、鉴权参数
- 频繁断线：调整心跳间隔与超时阈值，观察服务端负载
- 消息乱序：确保单连接顺序消费，必要时加序列号校验
- 解析失败：核对协议版本与字段定义，开启详细日志
- 内存泄漏：监控缓冲区大小，及时释放临时对象
